En este proyecto Limpio instalamos:
    - El Kit de inicio de Livewired
    - Ademas elegimos que ya por defecto no cree un sistema de login y registro
    - Laravel Volt -> Esto nos permite escribir tanto la logica como el codigo HTML en un mismo archivo
                     es conveniente porque si instalamos el Kit de Inicio por si queremos hacer modificaciones mas adelante

Despues nos registramos un usuario e iniciamos sesion
Por defecto veremos que esto nos proporciona un Dashboard
esto por defecto usa la libreria:
    - "Flux - LiveWire UI"
Esta por defecto ya nos da los componentes que podemos utilizar, para llamarlos usamos:
    - flux:NombreComponente

Cosas que tenemos instalamos con el Kit de inicio
    - TailwindCSS -> Esto esta en la carpeta: resources/css/app.css

Laravel solo tiene un punto de acceso y es en la carpeta Public, lo demas para poder ser leido tiene que ser compilado, cuando
ejecutamos el: npm run build, el compilador que usa Laravel es VITE
    Con esto nos damos cuenta que cuando aplicamos algun cambio de estilo en la pagina veremos a primeras que al recargar la pagina, no veremos los estilos aplicados
    eso es porque los cambios no han sido compilados y por tanto tenemos que ejecutar el comando de:
        - npm run build -> Cada vez que queremos ver los cambio hechos en los estilos
    Esto nos ayuda a que nuestro proyecto compilado no se vayan todas las utilidades de TailwindCSS ocupando espacio si no estamos usando todas
    Tambien la compilacion nos sirve para meter todos nuestros Script JS y estilos propios en la carpeta Public

    Para no tener que estar ejecutando el comando anterior a cada rato para ver los cambios, VITE nos proporciona el comando:
        * npm run dev
    Este comando mantendra encendido el servidor de VITE y por tanto cualquier cambio lo vamos a tener instantanio al guardar pagina

    Si al cerrar la terminal donde estabamos corriendo VITE, vemos que en nuestro proyecto se hecharon a perder nuestros estilos
    tenemos que ir a: public/ y eliminar el archivo "hot", asi Laravel se conectara al resultado de la compilacion y no a VITE

Estructura de la Base de datos que tenemos
    Tenemos estas Tablas:
        - Categories
        - Users
        - Posts
        - Tags
        - Comments
    Relaciones:
        - Uno a Muchos -> Categories a Posts
        - Uno a Muchos -> Users a Posts
        - Muchos a Muchos -> Tags a Posts
            * post_tag
        - Uno a Muchos -> Comments a Posts
Para ceearlas en el ORM primero debemos empezar con las tablas que no dependan de otras tablas
Creamos los modelos con su archivo de migracion:
    * php artisan make:model Category -m
    * php artisan make:model Tag -m
    - El de usuarios ya se creo con el sistema
    * php artisan make:model Post -m
    * php artisan make:model Comment -m
    * php artisan make:migration create_post_tag_table

Crear Registros de Prueba
    * php artisan make:factory CategoryFactory
Ejecutamos todo (Migraciones y Factories):
    * php artisan migrate:fresh --seed

Iniciar con el CRUD de categorias
    (Aqui le decimos que nos cree el controlador dentro de la carpeta Admin)
    * php artisan make:controller Admin\CategoryController --model=Category

Para ver aplicados los estilos en los elementos HTML, debemos de ejectuar el proyecto con:
    * npm run dev

Para los Post
    * php artisan make:factory PostFactory
Despues de todos los cambios de codigo volvemos a ejecutar las migraciones
    * php artisan migrate:fresh --seed
Creamos el controlador:
    * php artisan make:controller Admin/PostController --model=Post


Queremos generar el SLUG de forma automaticamente y que cuando vayamos escribiendo en el campo del Title tambien vaya cambiando
el campo del slug, si bien es cierto esto lo podriamos generar del lado del backend pero en ese caso no tenemos control del Slug
que se va generando y a nivel de CEO se recomiendo que el SLUG sea corto, ya que es comun que el titulo sea largo y no tiene sentido
hacer tambien el SLUG largo y que mejor solo contenga las palabras claves por eso es mejor manejar el SLUG del lado del Fronted
donde tambien podemos editar el campo despues de especificar el titulo

Queremos que cuando publicamos por primera un POST se agrege automaticamente la fecha en el campo "is_published"
para este caso vamos a usar los Observers que nos permiten esuchar diferentes eventos del ciclo de vida del modelo
es decir, cuando se crean, actualizan, eliminan
Para crearlos:
    * php artisan make:observer PostObserver

Texto Enriquecido
    En la parte del Cuerpo del post podamos agregar titulos, subtitulos, u otra forma en la que queremos que salga el texto en el post
    para esto tenemos el Plugin de QuillJS donde al usarlo nos mostrar la barra de menu tipo Office donde vienen las opciones para editar
    el texto

Agregar Etiquetas
    Queremos relacionar cada post con etiquetas pero no vamos a crearnos un CRUD con todo el sistema de tablas para la base de datos, mejor vamos
    a usar una libreria, donde podemos elegir creadas o crear nuevas en el momentos que las asignemos al Post
    La libreria es Select2, que para poder usarla tenemos que instalar JQuery en el proyecto
    (Igual hay que recordar que tenemos una tabla TAGS de donde queremos tomar los datos para mostrarlos en este componente nuestras etiquetas y la relacion de
    muchos a muchos con posts y categorias)

Traducir los mensajes de la aplicacion
    Por defecto como los mensajes de los errores de validacion salen en ingles, para esto existe el paquete de Laravel Lang
    Lo instalamos:
        - composer require laravel-lang/common
    Publicamos los archivos de traduccion con el idioma al que queremos traducir
        - php artisan lang:add es
    Esto nos genera una carpeta llamada LANG en la raiz del proyecto y dentro una subcarpeta por cada idioma al que queramos traducir
    por defecto los archivos que tenemos son traducciones internas que vienen por defecto en Laravel
    El archivo JSON es para traducir elementos de las vistas

        Si nos vamos a algunas de las vistas que ya nos genero el Kit de inicio veremos que donde sale el conenido esta como:
            {{ __('TEXTO') }}
        Esto es el contenido que sera traducido que esta establecido en el Archivo JSON estando como una llave el contenido por cada
        elemento que sale en esa sintaxis
